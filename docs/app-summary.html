How a price travels

Below the floor, the quote stops: the seller must request approval, and the request cannot be submitted without a competitor reading attached.

What it stops

  • Quotes below the floor — blocked, and only released by a manager decision with a reason on record.
  • Selling on yesterday's cost — if the cost basis moves and no one republishes, sending is frozen.
  • Screenshots of unknown vintage — every printed list and quotation carries its version, date and reference.
  • Silent discounts — each premium and discount is a named line, itemised per client.

Six checks and balances

  • No price typing anywhere in the seller's screen.
  • Freshness gate — a cost change freezes sending until republished.
  • Simulate before approve — impact in pesos per month, accounts that fall below floor, and accounts that cross above the nearest competitor.
  • Four eyes — the verifier can never be the drafter.
  • Immutable quotes — a sent quotation keeps its price, with a hash, after any later change.
  • Versioned prices — a price row is never edited; publishing closes the old one and inserts a new one.
The prototype runs today — 7 price lists, 12 products, 175 demo clients (50 bulk, 120 commercial), 8 users across 4 roles, 17 automated pricing tests passing. It is a working tool for the pricing cycle, not a mockup: quotes, approvals, publishing, notices and the audit trail all function. For IT

What it is today

  • Plain HTML and JavaScript modules. No build step, no packages, no server code. Runs from any static web host, a shared folder or a laptop.
  • Prototype data lives in the browser (localStorage), with export/import and reset. Nothing leaves the machine.
  • The pricing engine is one dependency-free file covered by 17 tests that run in the browser.
  • Money is whole centavos end to end — no floating-point drift, two decimals everywhere.

Path to production

  • The engine file moves unchanged into the server and the web client — the arithmetic is written once.
  • Every write already passes through one function; that becomes the API call. The event object is already the audit table row.
  • Seed collections map to tables; effective-dated rows map to a date-range column that makes overlapping prices impossible.
  • Needed for production: real accounts and passwords, server-enforced roles, a database, backups. The role switcher is a stand-in for login.
